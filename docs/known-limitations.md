# 已知限制与未实现功能

v4.4.0 提供普通逐条批准模式和由用户启用的多窗口自动模式。

1. **企业真实环境未验证。** 没有企业 Web 堡垒机、实际 Web 启动器参数或目标 Linux 测试账号；没有改动这些配置。真实 SSH/堡垒机兼容性、企业审计、签名要求、20 个真实 SSH 窗口负载需现场验收。
2. **不能接管旧二进制进程。** 只有运行改造程序的窗口才有 Native Bridge。原先未改造的已打开窗口无法事后添加；需经原 Web 流程新开本次程序窗口。
3. **终端状态识别有限。** 普通模式通过弹窗请用户确认目标窗口处于空闲提示符。自动模式仍检查认证、备用屏幕、原始鼠标、粘贴和后端状态。PuTTY 无法可靠识别所有手动启动的前台任务、未提交输入或远端提示。自动模式下提交命令或关闭子窗口前仍需核对终端状态。
4. **终端输入的范围。** 命令最多 2048 个 UTF-8 字节，观察最长一小时。语法取决于远端 Shell 或设备 CLI。前台键盘支持单键、组合键和有限长度的文本，粘贴需要远端程序开启括号粘贴。密码和 MFA 由用户输入。每个会话只允许一个活动的 MCP 任务。
5. **脱敏是尽力而为。** 认证/信任提示会关闭 Bridge，疑似秘密文本行按保留的上下文过滤，跨页时继续应用。输出缺口、未知格式、编码、任意文件内容和恶意输出仍可能阻止识别。开启观察即授权该窗口新输出被本机 Codex 读取并可能发往模型提供方；含秘密的会话应保持关闭。没有承诺企业 DLP/合规认证。
6. **屏幕语义有限。** `read_terminal` 返回安全转义后的主 Shell 字节流。`read_task_screen` 为预设交互任务返回有界文字帧。非 UTF-8 编码可能显示替换字符。接口不导出原始二进制数据。
7. **命令完成依赖提示符。** 只有观察到与发送前或 `expected_prompt` 匹配的提示符时，才可报告命令完成。提示符出现只反映终端画面，任务没有远端退出码。没有匹配提示符、输出缺口、断线、超时或人工干预可能导致 `unknown` 或 `timeout`。终端结果可能包含设备回显和相邻输出。
8. **中断和退出分开确认。** 已运行任务可单独请求一次 Ctrl+C。送出回执表示按键进入 SSH 队列，后续根据提示符和远端输出判断程序状态。非典型提示符、应用忽略按键或终端模式差异都可能使结果未知，需要用户核对。
9. **内存与历史有界且会丢失。** Broker/Adapter 重启不持久化任务或输出；新客户端不能取得旧客户端任务所有权。Native 离线期间可丢副本，输出间隙和游标明确披露。任务终态仅保留约 10 分钟。
10. **跨进程撤销存在传播延迟。** 本地关闭立即停止新采集和发送；Broker 收到断连后清理历史和权限，但无法撤回已被 Codex 读取的数据。旧在途消息/既有授权副本不能获得分布式零延迟撤销保证。
11. **安全边界为 Windows 同用户。** ACL、远程客户端拒绝、对端 PID/Token/创建时间检查已实现；不防同 SID 恶意程序、管理员、调试器或能代替用户点击的自动化软件。没有签名绑定或跨用户通信。
12. **审计为有界元数据日志。** v4.4.0 路径为 `%LOCALAPPDATA%\PuTTY-AI-v4.4.0`，记录来源、连接、会话、任务和送出结果。日志会轮转，当前 Windows 用户可访问。崩溃可能丢失尚未写盘的事件。
13. **性能报告范围有限。** 提供 C SPSC 微基准、20 个模拟 Native 的真实 Windows Named Pipe 压力、实际 PuTTY 原版与 AI 关闭的 GUI 对比，以及 Broker 崩溃时合成 C 前端事件响应。没有声称已经测得开启 AI 的真实 SSH 端到端吞吐、网络延迟或输入响应，也没有以一次采样证明性能提升。
14. **平台限制。** 本机 Windows x64；不支持 WSL/Linux/macOS/远端 Codex 直接访问 Windows Named Pipe。没有安装服务或自动启动项，Broker 会在 Adapter 退出后继续独立空闲运行，需用户结束进程或保留供其他客户端使用。
15. **vi 文件编辑范围。** 交互接口支持临时缓冲区和一个指定的已有普通文件。可把该缓冲区保存回原路径。新建文件、另存为、强制覆盖和任意 Ex 命令不在预设范围内。远端 vi 兼容性和当前模式决定按键效果。用文字帧确认画面，再继续发送操作。
16. **子终端共用 SSH 连接。** 主窗口最多可开四个子窗口，实际数量还受服务器通道限制。子窗口使用同一个远端用户权限，各有独立 Shell 状态。主窗口断开会结束所有子通道，MCP 宿主断开后已打开的子窗口可能继续运行。任务调度由 AI 宿主完成。
