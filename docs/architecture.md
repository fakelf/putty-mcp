# 架构、协议与状态机

```
AI 宿主 → 本地 stdio → putty-ai-mcp.exe → 同用户 Named Pipe → Broker
                                                       ↕
                                          PuTTY C 工作线程 ↔ PuTTY GUI → SSH
```

同一个 Rust 可执行文件提供 stdio 入口和 Broker 入口。宿主无参数启动 stdio。后台缺席时 stdio 进程按需启动同一个 exe 的 Broker 入口，Windows 不继承标准输入输出句柄。Broker 独立存活，多个客户端和 PuTTY 窗口共用。PuTTY 先开时，其工作线程会退避重连。

## Windows 进程和输出

AI 默认关闭。用户在已认证的 SSH 窗口开启观察后才有 AI 副本和工作线程。GUI 回调向预分配的 SPSC 环形缓冲做有界复制。工作线程执行重叠式 Named Pipe I/O，每批最多 16 块，空闲时约 250 ms 轮询。GUI 通过消息收到请求。普通模式显示非模态审批弹窗，自动模式在相同任务和会话校验下处理操作。

默认环形缓冲为 128 个 16 KiB 槽。每次输出回调最多复制 64 KiB。Broker 每会话缓存最多 2 MiB，每任务最多 256 KiB。原始字节游标揭示截断和缺口。断开关闭 AI 副本与本地审批，原 SSH 数据路径独立。

管道名为 `putty-ai-v440-<SID>`。仅当前用户通过 DACL 连接，拒绝远程访问。进程对端通过 PID 和 Token 校验用户，PuTTY 注册另核对进程启动时间。首实例标记确保同用户唯一 v4.4.0 Broker。Session ID 和客户端连接 ID 均随机生成。重连只重新发现可用窗口，不恢复原任务归属。

MCP 程序的 `--connection-report` 入口以独立的只读请求查询 Broker，返回已注册宿主数、已授权窗口数及指定会话是否已注册。查询不启动 Broker，也不注册新的 MCP 宿主。QwenPaw 的最近记录只展示阶段和计数，不把原始错误、路径、命令或终端内容放进报告。

## 命令调度

Broker 从 Adapter 的首次注册记录来源标签，给每条连接生成 client_id。每窗口最多一个未解决命令。普通模式的用户核对标签、会话编号、空闲终端和命令正文。自动模式由本地主窗口启用，适用于该窗口及其 AI 子终端。GUI 在检查同一代次、在线、认证状态和输入条件后发给现有 Ldisc。人工输入递增代次，使待处理请求失效。观察从收到 Native 已送出回执开始。

命令在 Broker 和 Native 两侧校验，最多 2048 个 UTF-8 字节。Native 只将正文转换为终端输入，LF 作为 Enter 发送，末尾缺少 Enter 时补一次。发送回执记录终端流中的发送位置和发送前可见的提示符。Broker 从发送位置观察捕获到的输出，使用原提示符或调用方的字面 `expected_prompt` 判断完成。输出仍保留设备或 Shell 自己的回显，任务 `exit_code` 为 `null`。同一有界缓冲保存终端流及分页位置。

## 一次中断

`interrupt_task` 仅接受发起者自己的当前运行任务。PuTTY 校验本窗口最后发送的任务和人工输入代次，普通模式会展示原脚本。Broker 检查任务仍在运行、未超时且仍占用这个窗口，再允许 Native 送出。GUI 消费一次允许，只向该 SSH 终端送一个 Ctrl+C。该操作允许原任务切换到备用屏幕。认证提示和粘贴状态仍阻止发送。任务完成、窗口状态变化或连接断开会使待处理中断失效，跨进程通知存在传播时间。

`interrupt_status` 独立于任务状态。按键送出后短暂进入 `interrupting`，按本地发送位置观察提示符。匹配时设置 `shell_prompt_observed`。观察期内未匹配到提示符时，按未知结果处理。取消与已发出命令竞态时保守报告未知结果。

## 独立交互任务

已认证的直连 SSH-2 后端通过现有 ConnectionLayer 开 `session` 通道，请求 PTY 后再启动固定的 `top` 或 `vi` 预设。任务自带 PuTTY Terminal 网格，在主窗口的终端区域绘制并接收键盘焦点。通道结束时移除任务画面，重新绘制原主终端。逐帧采样与主终端隔离。Broker 保留带帧号的有限缓存，屏幕更新不改变审批代次。按键采用窗口当前的批准模式并由 Broker 再校验，Native 最后核对当前通道、任务 ID、人工接管和退出状态。

交互任务和主终端共用每窗口一个 AI 活动任务的限制。SSH 退出状态、退出信号和关闭事件与本地按键回执分开。手动接管或断线会使 AI 的输入权限失效。固定命令由 Broker 和 Native 分别校验。

vi 的 UTF-8 文本请求走同一审批路径。Native 仅在该任务终端启用括号粘贴时，将开始序列、文本和结束序列一次送入 SSH 队列，无需模拟系统剪贴板。文字帧带有采集时的光标单元格坐标和粘贴可用性，Native 在发送时重新检查括号粘贴状态。请求状态只报告动作和送出结果，编辑效果由新帧核对。远端 vi 的模式会影响输入行为。

带 `path` 的 vi 任务绑定启动时选定的单个文件，启动时关闭 modeline，并用 `-m` 允许缓冲区编辑但禁用文件写入。处理保存时，远端检查当前缓冲区、原路径和文件元数据，临时启用写入执行一次普通保存，再恢复禁写。人工接管会使待处理操作失效。

## 前台终端输入

前台命令与 `attach_terminal` 任务使用主窗口或子窗口原有的 Terminal 和 Ldisc。`attach_terminal` 建立一个与 MCP 连接绑定的控制任务。每个操作绑定该任务与请求编号，按当前批准模式处理。GUI 在发送前核对任务、人工输入代次和可选的画面版本。组合键按当前终端模式编码，纯文本与括号粘贴分开处理。

前台画面取自正在使用的 Terminal，包含可见文本、尺寸、光标位置、备用屏幕和粘贴状态。人工接管或 `detach` 释放该任务的输入权限，原终端继续运行。发送回执、画面变化和任务结束分开观察。

## SSH 子终端

多子终端模式下，父窗口通过原 SSH-2 ConnectionLayer 开新 Shell 通道，在独立顶层窗口绘制普通终端。每个子窗口使用独立会话 ID、输出游标和任务状态，并在会话列表公开其父编号。同一父窗口最多有四个子窗口，通道共用已认证的连接和远端用户。子窗口不递归创建子窗口。新窗口在父窗口所在显示器的工作区选择位置，尽量少遮挡父窗口和已有子窗口。

打开和关闭是异步任务。Broker 保持请求归属和处理状态，宿主负责分配工作。每个子窗口仍只允许一条未解决命令。切回普通模式会撤销子窗口的 AI 权限，已打开窗口继续供用户手动使用。父 SSH 连接结束时，其子通道也会结束。

## IPC v2 帧

固定 64 字节小端头为 `PAI1`、版本 2、kind、负载长度、flags、session UUID、request UUID、输出序号和本地代次。全局帧上限为 128 KiB。

| kind | 用途 |
|---|---|
| 1 | Native 注册。PID 4 字节、创建 FILETIME 8 字节、HWND 8 字节 |
| 2 | 终端输出。至多 16 KiB 原始字节 |
| 3 | Native 轮询。4 字节确认码和 8 字节丢弃计数。发送命令时附加 8 字节发送前终端位置和至多 256 字节的提示符。发送 Ctrl+C 时附加 8 字节发送前终端位置 |
| 4、5 | 交互任务通道状态和最新文字帧，按任务 ID 路由 |
| 7 | 原前台终端的文字帧 |
| 11、13 | 命令或中断审批。客户端 UUID 16 字节、来源长度 1 字节、来源 UTF-8、脚本 UTF-8 |
| 12 | 定向撤销。任务 ID 在头中 |
| 15 | 确认发送单个 Ctrl+C。任务 ID 和代次在头中 |
| 16、17、18、19 | `top` 启动、`q` 审批、交互 Ctrl+C 审批及交互动作的单次发送许可 |
| 20、21 | vi 启动和普通退出审批 |
| 22 | 命名按键审批，`flags` 选择按键 |
| 23 | vi 文本审批，附加至多 1024 字节 UTF-8 文本 |
| 24、25 | vi 打开指定文件和保存审批，绑定同一个经校验的 UTF-8 路径 |
| 26、27、28 | 打开子终端、关闭子终端及审批后的单次执行许可 |
| 29、30、31、32 | 附加前台终端、请求输入、单次执行许可及释放附加 |
| 100、101、102 | Adapter RPC、回复、来源注册 |
| 103 | 自检查询。可附窗口会话 ID，回复只包含状态和计数 |

确认码 1 和 2 表示命令送出或未送出。3 表示本地中断已批准，等待 Broker 再校验。4 和 5 表示中断未送出或送出。

## 本地审计

`%LOCALAPPDATA%\PuTTY-AI-v4.4.0\audit.jsonl` 记录工具操作和送出结果，包括来源标签、连接 ID、会话和任务 ID。审计队列有界，文件轮转。日志只保存元数据。同一 Windows 用户进程是隔离边界，标签可用于追溯宿主配置和客户端声明。
